## Goal

Make the public examples surface small, coherent, and aligned with the first public-facing Spell release. The blessed set is:

- `hello-world`
- `coin-flip`
- `twenty-questions`
- `telephone`
- `auction`
- `chat`

This package should add the missing `telephone` example from the orchestration-game prompt, remove non-blessed examples from the public release surface, and update public docs so the example list and provider/setup wording match the curated set.

## Planned Changes

1. Add `examples/telephone.spl`.
   - Use the prompt-only orchestration-game wording:
     `Return an 8-step telephone relay report...`
   - Keep it as a natural-language `.spl` prompt, matching the other public examples.
   - Preserve the key constraints: fresh `!llm-self` relay at each step, bind each relay wording as the next message, report initial/relay/final wording, and do not use `agents/`.

2. Curate the example files to the blessed set.
   - Keep only the six blessed `.spl` files in the public examples directory.
   - Delete non-blessed `.spl` files and their companion docs/support data when they are no longer referenced.
   - Prefer deletion over moving to an `advanced` examples area for this release, because the release plan calls for a small public onboarding surface and this project has no backwards-compatibility requirement.

3. Rewrite `examples/README.md`.
   - Make it the canonical user-facing example list.
   - Present paid/authenticated provider use as normal; `--test` can remain an install smoke test elsewhere, not the examples default.
   - Keep OpenAI, Anthropic, Fireworks, and Codex CLI visible as provider paths without inventing new model identifiers.
   - Remove stale default-model text and old model-tier recommendations.
   - Include cost/budget caution for examples that make live calls.

4. Normalize public provider/model naming.
   - Remove the current asymmetry where some docs use friendly aliases such as `opus` while others expose transport-prefixed specs such as `openai-tc:gpt-5.4`.
   - Use judgment based on the existing CLI/provider config to choose public-facing names, with a preference for simple model names such as `gpt-5.4` when the default provider routing makes that unambiguous.
   - Keep transport/provider prefixes only where they are genuinely needed to disambiguate a non-default provider path, for example Fireworks-specific or Codex CLI-specific routing.
   - Apply the naming convention consistently across `examples/README.md`, retained companion docs, and public source/onboarding docs touched by this package.
   - Do not guess new model identifiers. If the implementation needs to change actual CLI alias behavior rather than only documentation wording, inspect `src/spell/cli.clj`, `config/providers/`, and focused tests first.

5. Clean or add companion docs for retained examples.
   - Keep docs concise: what the example demonstrates, how to run it, and roughly what to expect.
   - Update `hello-world.md`, `coin-flip.md`, and `twenty-questions.md` to remove stale model-tier language and overly specific internal history.
   - Add `telephone.md`, `auction.md`, and `chat.md`.
   - Avoid benchmark scoring, paper provenance, and internal failure history in companion docs. It is fine to mention telephone as a relay-loop example without citing benchmark results.

6. Update public source/onboarding references.
   - Update `AGENTS.public.md` example references to include `telephone` and remove non-blessed examples.
   - Update `examples/AGENTS.md` if that file remains part of the public source guide work.
   - Leave the broader decision about `config/AGENTS.md`, `test/AGENTS.md`, private `CLAUDE.md` files, and `.gitignore` to Work Package 3/5 unless needed to avoid broken package 4 references.
   - Do not rewrite `README.md` beyond a narrow examples-link consistency fix, because the release plan says README is user-owned for now.

7. Update TODO context through normal notebook flow only if implementation discovers a durable decision.
   - Completion of TODO `#272` should be captured by a notebook entry if the implementation materially completes the public example curation.
   - Do not manually edit `notebook/TODO.md`; the configured memory workflow handles todo completion from the entry.
