# Ship Plan: v0.2.0 Work Package 1

**Mode:** `$ship` standard mode; stop after planning for approval.
**Source plan:** `docs/v0.2.0-release-plan.md`, Work Package 1: Legal And Release Metadata.
**Scope:** `LICENSE`, `CHANGELOG.md`, and release-metadata consistency checks only.

## Goal

Make the repository minimally complete as a public software release by adding explicit MIT licensing and a terse changelog that frames `v0.1.0` as the paper/reproducibility release and `v0.2.0` as the first public-facing software release.

This plan intentionally excludes the conceptual language guide, README rewrite, API docs, examples cleanup, source-guide cleanup, and public archive cleanup. Those are separate work packages or user-owned work.

## Current Context

- `README.md` currently ends with `## License` and the single word `MIT`.
- There is no tracked `LICENSE`.
- There is no tracked `CHANGELOG.md`.
- `git tag --list` includes `v0.1.0`, and `git show v0.1.0` identifies it as `Spell v0.1.0` on commit `a3ce161`.
- `git log v0.1.0..HEAD` is empty on the current branch, so there are no committed post-`v0.1.0` implementation changes to summarize yet.
- The current worktree is dirty:
  - `D .claude/skills/run-benchmark/SKILL.md`
  - `M .gitignore`
  - ` M README.md`
  - `?? docs/`
- The README is user-owned for now and should not be edited unless a direct contradiction is discovered that cannot be fixed elsewhere.

## Planned Changes

1. Add `LICENSE`.
   - Use the standard MIT License text.
   - Copyright line: `Copyright (c) 2026 Luke Jen O'Connor`.
   - This matches `git config user.name` and the `v0.1.0` tag author.

2. Add `CHANGELOG.md`.
   - Use a terse Markdown format.
   - Include an `Unreleased` or `v0.2.0` section that does not enumerate docs cleanup, file moves, formatting, or release hygiene.
   - Because `v0.1.0..HEAD` has no committed changes in the current branch, do not invent scientific or architectural changes for `v0.2.0`.
   - Include `v0.1.0` as the paper/reproducibility-oriented baseline, with the concrete date from the tag: `2026-05-06`.
   - Keep wording compatible with the release plan: v0.2.0 is presentation/public-software oriented, but the changelog should not become a narrative release announcement.

3. Check consistency.
   - Confirm `README.md` still says MIT and does not contradict the new `LICENSE`.
   - Search existing public metadata for license/changelog/version claims.
   - Do not add Clojars, Docker, Homebrew, Python package, or other packaging claims.
