# Ship Plan: v0.2.0 Clojure API

**Mode:** `$ship` implementation after Plan Mode approval.
**Target branch:** `v0.2.0-dev`
**Source spec:** `docs/api.md`

## Summary

Implement `docs/api.md` as the v0.2.0 public Clojure API, including the current `docs/api.md` rewrite and `docs/configuration.md` deletion.

The implementation branch should target `v0.2.0-dev` and open a PR back to `v0.2.0-dev`. Current local dirty spec changes must be preserved and included; they are not unrelated work.

## Key Changes

- Replace public `spell.api/run :provider` with required `:lm-profile`, while keeping `:agent` required at the API boundary.
- Add LM profile loading from `config/lm-profiles/*.edn` using public keys from the spec: `:provider`, `:lm-profile-name`, `:default-model`, `:default-reasoning-effort`, `:default-agent`, provider transport/auth/timeout/pricing keys, and test-provider keys.
- Migrate checked-in provider configs from `config/providers/*.provider.edn` to `config/lm-profiles/*.edn`; update public docs and source guides from provider config to LM profile where needed.
- Update agent config loading to accept public names: `:agent-name`, `:agent-description`, `:system-prompt`, `:default-lm-profile`, `:default-budget`, `:format-retries`, and `:available-agents`.
- Preserve internal CLI and benchmark behavior by adapting them to call the new API vocabulary, not by keeping legacy public `run` keys.
- Make `spell.api/run` validate input strictly: require exactly one of `:prompt`/`:init`, require `:lm-profile` and `:agent`, reject removed run options such as `:provider`, `:trace`, `:usage`, `:user?`, `:verbose`, `:thinking`, `:prefill?`, `:format`, `:retries`, suffix grammar options, and transport/provider constructor keys.
- Change run behavior to match the spec: trace iff `:trace-dir` is supplied, return `:usage-tracker`, flush but do not close caller-owned `:log-writer`, enable `:user` iff `:user-reader` is supplied, and allow run-level `:model` / `:reasoning-effort` overrides.
- Keep low-level provider constructors and existing provider records available for internal/programmatic use; the breaking surface is `spell.api/run` and public config vocabulary.

## Test Plan

- Update and run focused API/provider/agent tests: `clj -M:test-fast`.
- Add regression coverage for `:lm-profile` path, inline LM profile map, existing provider instance as LM profile, required fields, unknown/removed option rejection, `:usage-tracker` return key, trace-dir-only tracing, log-writer not closed, user-reader registration, and run-level model/reasoning overrides.
- Update CLI and benchmark API tests so existing CLI/model-prefix behavior still works through the new API.
- Run smoke checks:
  - `bin/spell -h`
  - `bin/spell -t "Return a short greeting"`
  - `git diff --check`

## Assumptions

- `v020 dev branch` means `v0.2.0-dev`.
- The current uncommitted `docs/api.md` and deleted `docs/configuration.md` are the authoritative spec and should be shipped in the PR.
- v0.2.0 may make breaking public API/config changes; compatibility is maintained for CLI and benchmark adapter behavior, not for old `spell.api/run` option maps.
- A notebook entry is warranted after implementation because this is a release-shaping API/config migration.
