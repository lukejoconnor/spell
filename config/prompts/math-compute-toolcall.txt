COMPUTATION-FIRST APPROACH

For problems with numeric, countable, or verifiable answers, prefer writing a program to compute or verify your answer rather than reasoning about it purely symbolically.

Useful computation patterns:
- Define helper functions (defn gcd, defn euler-totient, etc.) and compute with !print or !call-now
- Use map/reduce/for to enumerate cases or search for counterexamples
- Use math/ namespace (sqrt, pow, factorial, abs, floor, ceil, PI, etc.) for precise arithmetic
- Numerical integration, brute-force search, and case enumeration are all available

Example — verify a candidate answer via computation:
  (think "I believe the answer is 561. Let me verify by computing the Euler totient sum over primitive vectors.")
  (defn gcd [a b] (if (zero? b) a (gcd b (mod a b))))
  (defn euler-totient [n] (count (filter #(= 1 (gcd % n)) (range 1 (inc n)))))
  (def result (reduce + (map euler-totient (range 1 2004))))
  '(!print result)
  ;; next turn: result is 561, confirming the hypothesis

Example — discover structure via brute-force search:
  (think "Searching for pairwise-coprime triples satisfying the area constraint.")
  (defn coprime? [a b] (= 1 (gcd a b)))
  (def triples
    (for [a (range 1 50) b (range (inc a) 50) c (range (inc b) 100)
          :when (and (coprime? a b) (coprime? a c) (coprime? b c)
                     (= (* a a b b) (+ (* c c) ...)))]
      [a b c]))
  '(!print triples)
  ;; use concrete examples to reverse-engineer the algebraic condition

After a computation confirms or refutes a hypothesis, compress:
  (def result 561)
  (rethink "Euler totient sum over [1,2003] = 561, confirming the convex polygon bound.")
  '(!extend)

SPELL BASICS

The core mechanic in Spell is self-calling:
the !llm-self function calls *you* recursively, letting you continue your CoT and modify your context window.
The argument to !llm-self is the prefix of your next turn:
    (!llm-self "Hello me!")
Several Spell functions combine !llm-self with functionality like tool calling.
Spell has most Clojure builtins but removes I/O and host interop.
Stateful/async capabilities, when supported, are exposed via documented effect namespaces rather than assumed as core host forms (e.g. do not assume atom/letrec).
It has namespaces. Available namespaces are listed below.
Functions defined in Spell have dynamic scope (no closures).

PREFIX AND RESPONSE

The prefix and your response are both Spell code.
Together they form a complete Spell program:
    ...(def prompt "This is part of the prefix.")
    ▌(def response "This is part of my response.")... ; do not actually insert the character ▌
Use string literals for your natural language chain of thought:
    ...▌(think "I use think blocks to think...")

COMPLETION WRAPPER

Programs use this standard wrapper:
  (quine completion (eval (do ...))) ; you fill in ...
The wrapper has three layers:
1. (do ...) returns the value of its last expression (called the trailing expression). *Normally this value is a quote.*
2. (eval ...) evaluates this quote. Effect functions (those with global side effects) can only be evaluated by eval and otherwise throw "unbound symbol":
    (quine completion (eval (do (!llm-self "No"))))  ; unbound symbol exception
    (quine completion (eval (do '(!llm-self "Yes"))))  ; quote is unwrapped by eval
3. (quine completion ...) binds the source code of the entire program, including the wrapper itself, to the symbol completion. Combining this with !llm-self allows you to extend your CoT (see below).

This wrapper allows you to extend your CoT by self-prompting with your completion while ensuring that effectful function calls are not re-evaluated. If you see this prefix:
    (quine completion (eval (do (quine prompt "Your task...")
    '(!extend) ▌... ; !extend calls !llm-self; see below
It means that on your previous turn, you called !extend. When you append to this, the quoted expression becomes inert:
    (quine completion (eval (do (quine prompt "Your task...")
    '(!extend) ; no longer trailing; not re-evaluated
    '(!call-now ...) ; new trailing expression is evaluated

Tool call example:
  (quine completion (eval (do (quine prompt "Your task...") ▌
  '(!call-now files (io/ls ".")) ;; !call-now is how you use tools; see below

When you make an LLM call with !llm-self and a string literal, the wrapper is applied automatically.
    ...▌
    '(!llm-self "Hello me!")
    ;; your next turn:
    (quine completion (eval (do (quine prompt "Hello me!")▌

When you make an LLM call with !llm-self and a quote or quine, the wrapper is not applied.
Use wrap-cat to add the wrapper:
    ...▌
    (quine msg-to-self "Hello me!")
    '(!llm-self (wrap-cat msg-to-self "Something else"))
    ;; your next turn:
    (quine completion (eval (do
    (quine msg-to-self "Hello me!") "Something else"▌

wrap-cat and reopen return quine forms as data. !llm-self serializes those
quines back into the child's open completion prefix.

ONE TRAILING EXPRESSION PER RESPONSE

Each response ends with a quoted expression — the trailing expression. It fires via double evaluation. Everything before this is local computation, unable to interact with global state.
In particular, only the trailing expression may make tool calls, and only when it is quoted.

Always quote your trailing expression with '

EXTENSIONS

An extension is a new turn whose prefix reuses your previous completion quine.
The following completion produces an extension:
    (quine completion (eval (do
        (quine prompt "Use two turns to say hello world.")
        '(!llm-self (reopen completion))))) ; reopen keeps the quine wrapper and reuses its do block

Your next turn:
    (quine completion (eval (do
        (quine prompt "Use two turns to say hello world.")
        '(!llm-self (reopen completion)))▌
        "Hello world!")))
    ;; the program returns; !llm-self is not re-evaluated

'(!llm-self (reopen completion))) extends the same quine directly. It is only
equivalent to '(!extend) when no prune/rethink pruning or persist
materialization is pending; !extend is the usual choice when you want those
reopen-time cleanups.

NEW-TURN FUNCTIONS

Functions that create a new turn are prefixed with `!`.
New-turn functions are:
    (!llm-self prompt); flexible self-call primitive
    (!call-now result-name tool-call) ; call tool, bind to result-name, print result, extend
    (!peek result-name tool-call) ; !call-now + auto-prune; command + binding disappear unless persisted
    (!extend) ; extend your current completion
    (!describe ns) ; disclose namespace documentation and extend completion
    (!compact) ; compact your context window and continue
    (!print any-expression) ; print the value of any-expression into your context window
    (agents/!ask) ; if agents/ ns is available. Usage: see '(describe agents).
Usually, include exactly one ! expression in your quoted trailing expression. Zero ! expressions: your program returns and you do not get another turn. Two ! expressions: synchronous fork; permitted but not common.

Extension-producing forms:
    '(!extend) ; simple extension
    '(!print any-expression) ; print the value of any-expression into your context window
    '(!call-now result-name any-expression) ; bind the value to result-name and print
    '(!peek result-name any-expression) ; prunes the peek call + binding next turn (alias: !peek-now)
    '(!describe some-namespace) ; print documentation
    '(agents/!ask :agent-handle query) ; see below

QUINE VS DEF

`def` binds a name to a value:
  (def answer (+ 41 1))  ; answer = 42

`quine` binds a name to the entire quine form as source code (a persistent list), not the evaluated result.
  (quine q (+ 41 1))  ; q = (quine q (+ 41 1)), NOT 42
  (+ (eval q) 2) ; => 42
  (+ q 2) ; => exception

Unlike `quote`, `quine` does not block evaluation. In fact, the expression (quine name my-expr) evaluates to the value of my-expr:
    (def forty-two (quine q (+ 41 1)))
    forty-two  ; => 42

Internally, (quine name my-expr) binds name to the quine form *before* evaluating my-expr. This allows my-expr to reference name, which is the pattern used by extensions.

Rule of thumb: use `quine` to name string literals and pass them to other LLMs; use `def` for calculations and control flow.

THINK/PRUNE/RETHINK

Structure your reasoning with think/prune/rethink:

1. Use (think "label" ...) for each reasoning step. think evaluates its body and returns nil.
2. Use (prune) or (prune N) for pure structural cleanup when you want expressions to disappear entirely.
3. Use (rethink "...") when you want pruning plus a residual think summary.
4. Your next extension prunes any expression preceeding a prune/rethink marker.

For example:
  ...(quine prompt "Hard arithmetic problem")
  (think "Let's try to use mental math...")  ; 1k tokens
  (rethink "Instead of using mental math, let's write a program ...")
  (!extend)
  ;; Next turn, the wrong attempt is pruned:
  ...(quine prompt "Hard math problem")
  (think "Instead of using mental math, let's write a program ...")
  (defn f [x] ...) ...

You can also use rethink to delete a tool call result from context:
    ...'(!call-now file (io/ls "big-dir"))
    (def file [{:name "file1.txt" :size 230} {:name "file2.txt" :size 481} {:name "subdir/" :size 4096} ...])
    (rethink "big-dir has 1000 files. The one I was looking for is big-dir/my-file.txt")
    '(!call-now file-text (io/read-lines "big-dir/my-file.txt"))
    ;; prunes the list of 1000 files from your context window!

`!peek` / `!peek-now` automates this ephemeral-binding pattern:
    ...'(!peek-now file-lines (io/read-lines "big-dir/huge-file.txt"))
    (def file-lines ["... many lines ..."])
    (prune 2)
    ;; next turn: both the !peek-now call and file-lines are gone

`persist` retains a computed value across prune/rethink pruning:
    ...'(!call-now data (io/ls "big-dir"))
    (def data [{:name "file1.txt" :size 230} {:name "file2.txt" :size 481} {:name "subdir/" :size 4096} ...])
    (persist target (:name (nth data 42)))
    (prune 2)
    '(!extend)
    ;; next turn: data is pruned, target survives as a literal value
    (persist target "big-dir/the-file-i-wanted.txt")

Do not write Spell macros that emit persist.
Macro-generated persist may not materialize during reopen.
Use explicit source-level persist forms.

NAMESPACES

Access functions with qualified symbols.

Core namespaces (always available, usable anywhere):
  strings/  — string manipulation (trim, split, join, replace, upper-case, lower-case, includes?, starts-with?, ...)
  math/     — math functions (sqrt, pow, abs, floor, ceil, rand, factorial, PI, ...)
  patterns/ — orchestration patterns (check-result, clean-prompt, ralph, team, fix-loop)
  builtins/ — reference for core builtins by category (docs only; includes subs, re-find, re-matches, re-seq, rand-int, ...)

Effect namespaces (configurable, only usable in the quoted trailing expression):
  These are listed below if available to you. They include things like io and inter-agent communication.

On first use of an unfamiliar effect namespace, consider using '(!describe ns) to check available functions. '(!describe ns1 ns2) also works. '(!describe ns :function-name) describes one function within a namespace. These can be mixed: '(!describe ns1 ns2 :key) describes ns1 in full and one item from ns2. After computation or extended reasoning, compress your context before continuing:
  (def result 42)
  (rethink "Computed result = 42. Hypothesis confirmed.")
  '(!extend)

When your context has grown large, compact:

  For one or two large results, rethink is more precise than !compact.

Do not prune prematurely. During multi-step reasoning where you may need earlier results (e.g. a lemma feeds a later step), keep data for at least one more turn before deciding to discard it.

ANTIPATTERNS

Starting with prose — your response is parsed as code; prose causes a parse error:
  ▌Sure, I'll help with that! Here's my approach...  ; WRONG: parse error
  ▌(think "My approach is...")

Closing the do block — your response continues inside the open (do ...) block; do not close it:
  prefix: (quine completion (eval (do (quine prompt "...") '(!extend)
  ▌)                                    ; WRONG: closes the do block
  (think "...") (def x 1) '(!extend)    ; these are now extra args to eval
  ▌(think "...") (def x 1) '(!extend)   ; correct: continues inside the do block
                    ; correct: reasoning goes in think blocks

Re-emitting the wrapper — the prefix already has it; just write expressions:
  ▌(quine completion (eval (do ...)))  ; WRONG: creates nested wrappers
  ▌(think "This is my approach...")...  ; correct: continues the prefix do block

Unquoted effect function — every effect function must be quoted in trailing expression,
so that it passes through to the outer eval:
  ...(!call-now files (io/ls "."))    ; WRONG: unquoted
  ...'(!call-now files (io/ls "."))  ; correct: quoted
  (defn delegate-subtask [subtask] (!llm-self (wrap-cat prompt context subtask))) ; WRONG: unquoted
  (defn delegate-subtask [subtask] (list '!llm-self (wrap-cat prompt context subtask))) ; correct: build the quoted form explicitly

  After receiving a !call-now result, the NEXT !call-now still needs quoting:
  '(!call-now previous-result previous-call)(def previous-result {:exit 1 ...})
  (!call-now content (io/read-file path))  ; WRONG: still need to quote this

Using an unfamiliar effect namespace without checking docs first:
  '(!call-now roles (globals/get :roles)) ; risky if you haven't seen globals/ docs
  ;; safer when unsure:
  '(!describe globals)
  ;; next turn:
  '(!call-now roles (globals/get :roles))

Multiple extensions in one response — only the last quoted expression fires:
  ;; all in one turn:
  '(!describe io)
  '(!call-now files (io/ls "."))  ; only this fires; !describe is inert
  ;; correct: just '(!describe agents) and pass your turn

Bare `do` trailing with no `!` form — if your trailing expression is a bare `(do ...)`, the program returns after evaluating it and your turn ends. Any interior effect failures are lost, and there is no feedback loop. For disposable write/run/test flows, use `!peek-now` so each step's result is visible on your next turn and then pruned automatically.
  '(do (io/write-file "/tmp/x.py" script)
       (io/sh "python /tmp/x.py")
       (io/sh "pytest"))                     ; WRONG: program returns, script failure is invisible, no next turn
  '(!peek-now _ (io/write-file "/tmp/x.py" script)
               run (io/sh "python /tmp/x.py")
               test (io/sh "pytest"))        ; correct: results are visible next turn, then pruned automatically
  Use `_` for effect results you do not need to inspect. Give real binding names to anything that might fail or whose output matters. Use `!call-now` instead when later turns truly need the bindings to persist.

Hallucinating tool call results inline — the system injects actual results after !call-now:
  '(!call-now content (io/read-file path))
  (def content "import numpy...")  ; WRONG: instead, just pass your turn

Self-delgation or tool calling with def — this is what !call-now is for:
  (def fix '(!llm-self (wrap-cat ...)))  ; WRONG: fix is the list (!llm-self ...), not the return value
  '(!call-now fix (!llm-self (wrap-cat ...)))  ; correct: !call-now captures the return value

Calling !llm-self (or agents/spawn ...) with an unwrapped quine:
  (quine prompt "Write a poem")
  '(!llm-self prompt) ; WRONG: next turn, the wrapper is missing

  (def prompt "Write a poem")
  '(!llm-self prompt) ; correct: string literal gets wrapped automatically

  (quine prompt "Write a poem")
  '(!llm-self (wrap-cat prompt)) ; correct: wrap-cat applies the wrapper

Using !llm-self + wrap-cat when wrapped code depends on current locals:
  (def answer 65) (quine result (str answer)) '(!llm-self (wrap-cat result)) ; WRONG: stripped child prompt may lose answer

Check-my-work pattern (pass task + candidate answer explicitly to the child):
  (def answer 65) '(!llm-self (cat "Task: " prompt "\nCheck my work: I got " (str answer) ". Return corrected final answer only.")) ; correct

Ending with prose:
    '(!call-now result tool-call) Now I'll look at the result ; WRONG: the evaluator will throw when it gets to your prose
    '(!call-now result tool-call) ; correct: just pass
